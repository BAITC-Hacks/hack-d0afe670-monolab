## Issues Resolved

### 1. Pothole Misclassification (AI reporting "Повреждённый люк" for potholes)

**Root cause:** Domain gap + model behavior
- Model trained on direct road photos (RDD2022, Roboflow)
- User tested with **webcam photo of a phone screen** showing a pothole
- Dark circular hole on bright rectangle → model guesses `sunken_manhole` (~71% confidence)
- Manhole is the strongest class (AP50 0.846 in RESULTS_V1.md)

**Solution:**
- Explained limitation to user
- Recommended: point camera at actual road, not at another phone's screen
- Production threshold stays at 0.4 (per RESULTS_V1.md decision)

---

### 2. Manual Class Selection Removed

**Old behavior:**
- Step 2 showed `DefectClassConfirm` component with 5 class buttons
- User had to manually correct AI when it got the class wrong

**New behavior:**
- AI decision is **read-only** — shown as: `"Класс: Глубокая яма · 73%"`
- No manual selection UI
- If no detection above threshold (0.4), button disabled with warning

**Rationale:** Manual selection was a workaround for misclassification. Better to fix the photo quality (no phone-screen shots) than add a picker.

---

### 3. Detection Boxes Fixed

**Bugs:**
- **Bug A:** Boxes positioned as `%` of container, not accounting for `object-fit: contain` letterboxing → boxes could appear in black bars off the image
- **Bug B:** When model returned zero detections, UI still defaulted to `pothole` — sidebar said "Глубокая яма" while photo showed "Дефект не распознан"

**Solution:**
- Compute visible image rect inside the container (accounting for letterbox/pillarbox)
- Map YOLO pixel coords → actual rendered image position
- If `detections.length === 0`, disable "Далее" button and show warning: *"Дефект не распознан — снимите ближе к дороге, без экрана телефона."*

**Code changes:**
- `frontend/src/components/flow/PhotoScanView.tsx`: new `imageContentRect()` helper + `ResizeObserver` for responsive layout
- `frontend/src/App.tsx`: removed `confirmedCvClass` state; replaced with `cvResult?.primary_defect` directly

## Current Flow (Step-by-Step)

### Step 1: Photo Capture
- Camera or webcam (no gallery upload)
- GPS auto-fetched or set on map later

### Step 2: AI Validation
- YOLO26 inference → detection boxes overlaid on photo (red = hazard, green = warranty)
- Sidebar shows: `"Класс: <label> · <confidence>%"` (read-only)
- If no detection: warning + button disabled
- If detected: "Далее — подтвердить место" enabled

### Step 3: GPS Confirmation
- Yandex Map with warranty road segments (blue polylines)
- User confirms or adjusts marker

### Step 4: Contract Match
- Spinner: "Ищем ответственного подрядчика…"
- **If warranty found:** show contractor card → step 5 (warranty mode)
- **If no warranty:** auto-advance to step 5 (general mode)

### Step 5: Complaint Generation
- Warranty mode: "Сформировать претензию" → contractor + contract info
- General mode: "Сформировать заявку" → akimat maintenance request
- QR code for eGov Mobile auth → "Отправить в Акимат"

### Step 6: Success
- "Жалоба зарегистрирована" + ticket number
- "Сообщить о другом дефекте" → restart
